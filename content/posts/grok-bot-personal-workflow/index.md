我最近用 Grok Bot 搭了一个“日程管家”，通过滴答清单官方 MCP 接管我的个人待办，并把它和我平时写代码的主力工具 Codex 打通。这篇文章主要聊聊我日常是怎么用它的：传统直接记待办有哪些不足，怎么把 GTD 和四象限的思想落到实际规则里，以及它怎么帮我同步 Codex 进度、按场景挑任务，并在我的许可下往前推进工作。

## 一、传统直接记录的三个不足

以前直接用待办软件手动记事时，我经常遇到三个很难靠自律解决的问题：

1. **记录时的分类负担太重**  
   每次冒出一个念头，不仅要敲进输入框，还得当场决定它属于哪个清单、打什么标签、设哪天截止。正在忙别的事时，多做几步分类都会打断思路，最后要么随手塞进收集箱不再打开，要么干脆漏记。
2. **只记了笼统目标，没记“下一步”**  
   随手记下的往往是“学英语”“做个插件”“整理面试资料”这种大词。等真正腾出空来打开清单，看到笼统的标题还是很难立刻动手，因为还得重新想第一件事具体干什么。
3. **记事的地方和干活的地方脱节**  
   对平时用 AI 写代码、查资料的开发者来说，真正推进项目的现场在终端、IDE 和 Codex 对话里。常常是我和 Codex 聊完方案、改完代码，滴答清单里的任务还停留在几天前的状态。干完活再去待办软件里一条条补备注、勾子任务，非常耗费精力。

因此我给日程管家定下了明确分工：想法随口丢给它，由它负责归类、拆解第一步、跟进 Codex 进度，并根据我当下的精力和场景推荐任务。

为了减少维护负担，我把滴答清单压到了最简，只保留 `Work` 和 `Life` 两个清单：`Work` 放上班的本职工作，由我自己维护，日程管家不碰；`Life` 则装下所有个人事务，无论是写独立产品（如 X 信息流过滤插件 Clearflow）、学公开课、做交易研究，还是日常买雨衣、拿快递，只要是个人的事全部放进 `Life`。

## 二、GTD 与四象限的落地用法

在 `Life` 清单内部，我采用了 **[GTD（Getting Things Done）](https://gettingthingsdone.com/what-is-gtd/) + [四象限法则（艾森豪威尔矩阵）](https://www.todoist.com/productivity-methods/eisenhower-matrix)** 的组合：用 GTD 把零散想法变成可执行的动作，用四象限决定先后顺序。

### 1. 四象限：给 Agent 明确定义什么是“重要”

通用的[艾森豪威尔矩阵](https://www.todoist.com/productivity-methods/eisenhower-matrix)按“重要”和“紧急”两个维度把事情分成四个象限：

- **第一象限（重要且紧急）**：有明确期限或紧迫后果的要事，优先立刻处理；
- **第二象限（重要不紧急）**：关乎长期目标与核心产出的事，需要留出整块高专注时间推进；
- **第三象限（不重要但紧急）**：需要尽快处理但长期价值不高的日常琐事，适合抽空快速清掉；
- **第四象限（不重要不紧急）**：无紧迫性的杂事或消遣，尽量少占精力。

[滴答清单自带四象限视图](https://help.dida365.com/articles/6950381682822217728)，支持结合任务日期和优先级等条件筛选展示，规则也可按需编辑。我让日程管家直接用滴答清单的优先级配合这套视图来管理任务。

落地时最关键的一步，是**给 Agent 明确定义什么是“重要”**。  
如果不给具体标准，Agent 很容易把“有截止时间”当成“重要”。有一次我让它提醒我晚上去拿纸，因为它看到有明确的当天时间点，就把“拿纸”判成了“重要且紧急”。但有时间点只说明它在那个时刻需要办，属于“紧急”，并不代表它对我的长期目标有多重要。

为此，我给它定了一条判断“重要”的标准：**只有与长期能力积累、职业发展、收入增长或工作效率直接相关的事，才算“重要”。**  
有了这条准绳后，“拿纸”这类带时间点的日常琐事会被归入“不重要但紧急”；而学英语、开发独立产品、准备求职面试则排在中高优先级里。什么事算重要由我自己定，Agent 按标准辅助归类，遇到判偏的情况我再随时调整。

### 2. GTD：随口收集、当场拆出“下一步”

[GTD 方法论](https://gettingthingsdone.com/what-is-gtd/)包含收集、厘清、组织、回顾与执行五个环节，落到日常里主要是四条规则：

- **随口收集与 X 收藏筛选**：平时想到什么事，我直接发消息交代一句，它就会在 `Life` 里勾掉已完成项、记上新待办。此外它每天中午会扫描我最新的 X 收藏；早期它扫到内容会直接往滴答里建阅读任务，容易制造噪音，后来改成了**默认只提建议、不自动建任务**，只有遇到值得深入研究的内容、经我点名要求时才正式立项。
- **记事时当场拆出“下一步”**：GTD 讲究把模糊的事变成具体的下一步物理动作（Next Action）。我定的规矩是**凡是记进清单的事，必须当场拆出第一步**。比如记“英语学习”时，第一步拆成“先写下学英语主要是为了什么（听说、读文档还是准备面试）”；又比如记“自学斯坦福 CS329Z 中文课程”时，第一步直接拆成“先看课程目录里的学习路线，从第 1 讲读起”。看到具体动作，启动阻力就会小很多。
- **精简标签**：任务靠状态标签（下一步、项目、将来或许、采购、等待）和情境标签（阅读、外出差事、在家）区分；而很多教程推荐的“预估耗时”标签太主观，维护成本高于收益，被我直接省掉了。
- **同步不替代回顾**：我目前选择先不设固定的周回顾例程，主要靠日常自动同步和早晨简报更新清单。但自动同步完成状态只能减轻改清单的负担，不能替代 GTD 的“回顾（Reflect）”——某一步做没做完可以靠同步对账，但一件事还值不值得继续投入、方向要不要调整，依然需要我自己看清单时判断。

## 三、结合当前场景选任务：清晨啃难事，碎片时间做手机小步

清单里的待办一多，每次从头扫一遍挑任务还是容易犹豫。因此我每天最高频的用法，是让它结合我当时的精力和所处场景帮我挑任务。

- **早晨最清醒的时刻**：清晨是我一天里大脑最清醒、专注力最高的时候。每天早上它会生成一份专注简报，按“今天最该做的一件事（重要且消耗脑力的核心任务）”“顺手的浅事”和“别再拖的事”排好，并剔除每天吃补剂这类固定重复的日常习惯。我早上坐到电脑前也会直接让它推荐两三件最需要动脑子的重头戏（比如优化交易监控、准备面试项目或推进核心开发），趁精力最好时集中攻克。
- **排队、坐地铁与外出场景**：到了白天外出办事、排队、坐地铁，或者午休、傍晚不想开电脑时，我会直接告诉它当前场景，让它推荐能在手机上完成的任务。它会跳过需要电脑深度思考的大项目，挑出拿手机几分钟就能做完的下一步——比如顺手确认并勾掉已办完的日常事项，或者读一段整理好的学习与求职资料。手机上能做的不一定都是琐事，有时重要项目里也包含刚好能在手机上阅读或确认的一小步，趁碎片时间清掉，回到电脑前就能直接进入核心开发。

## 四、联动 Codex：自动同步进度与许可后推进

真正把“记事”和“干活”串起来的，是让日程管家和我电脑上的 Codex 协同工作。

1. **自动统计 Codex 任务更新进度**  
 我平时开发插件、写代码、改简历或做调研都在 Codex 对话里进行。日程管家在白天会定时读取我和 Codex 的对话进展，先在滴答 `Life` 清单里找到同主题的既有任务，把已完成的步骤打勾，把接下来的下一步加为排在最前面的子任务，并在任务备注里补上进展摘要；如果没有实质改动则保持静默，不发消息打扰。
2. **在我的许可下主动联系 Codex 往下推进**  
 读取进度可以定时自动跑，但要调动 Codex 真正动手干活，必须经过我的明确许可。比如我在 X 上刷到斯坦福 CS329Z 课程的帖子，觉得值得系统学习，就让日程管家把公开的课表、课件和阅读材料整理交给 Codex，生成一套中文自学课程，随后由日程管家在滴答清单里建好自学任务并拆出第一步。同样地，当我想对收藏里的 Agent 评测或代码审查方法做深入调研时，也是先由它列出候选、经我核对拍板后，再交由 Codex 结合我的本地项目整理成参考教程。

## 五、真实局限与人机分工

实际用下来，这套工作流也有需要注意的局限：一是当我让它从待办和收藏里挑任务推进时，它有时会图省事只看滴答旧备注或对话末尾几句，把已经做完上架的插件任务又拿出来推荐，需要我提醒它去核对完整进展；二是纯靠语义匹配去重时，偶尔仍会漏掉个别重复条目。

这也让我更清楚人机之间的分工边界：收集想法、拆解第一步、同步 Codex 进度、按清晨或地铁手机场景筛任务，这些日常维护交给 Agent 确实省心；但决定什么事情真正重要、审视方向是否值得继续投入，以及何时授权 AI 动手推进，始终要由人自己把关。
