# 内容与引用规范

## 证据等级

| 标记 | 含义 | 可写的结论 |
| --- | --- | --- |
| `source` | 来自论文、官方文档或源码 | 资料说明了什么 |
| `code` | 作者编写或阅读了可运行代码 | 代码如何实现 |
| `test` | 有自动测试或固定样本检查 | 在测试条件下结果如何 |
| `experiment` | 有可复现实验 | 在实验设置下结果如何 |
| `production` | 有真实生产环境证据 | 在该系统和时间范围内结果如何 |
| `opinion` | 作者判断 | 作者认为什么，以及理由 |

不能把测试结果写成生产效果，也不能把观点写成事实。

## 来源顺序

优先使用：

1. 论文原文、官方文档、规范、源码、发布说明。
2. 作者本人博客、演讲或代码仓库。
3. 有明确方法和数据的第三方评测。
4. 社交媒体讨论，只作为线索或观点来源。

最新模型、价格、API 参数、产品功能等容易变化的信息，发布当天重新核查，并写明访问日期。

## 引用与转载

- 用自己的话解释，必要时短引用原文。
- 不复制长段帖子、论文、付费文章或课程材料。
- 第三方图片默认不搬运；需要说明时自行重画，并标明依据。
- 代码引用遵守原项目许可证，保留必要的版权和许可信息。
- 网站文章与示例代码分别声明许可证，第三方材料不受本仓库许可证覆盖。

## AI 使用

可以用 AI 帮助整理资料、改写段落、检查逻辑和生成测试草稿。

不能用 AI：

- 代替原始资料核查。
- 编造实验结果、读者评价、专家身份或项目经历。
- 批量生成大量相似文章争取搜索流量。

文章 front matter 可记录 `aiAssisted`，仅作为内部元数据，不显示为文章尾注。公开文章不添加“本文由 AI 辅助研究与撰写”等制作声明、核查过程或检查通过报告；这些记录留在私有工作区。来源链接、影响结论的局限和示例性质照常保留。

## 隐私与保密

公开前删除：

- API key、token、cookie、邮箱、手机号、内部域名和私有路径。
- 公司代码、客户数据、内部截图、未公开架构和指标。
- 面试中的公司信息、面试官信息和非公开题目。

项目经历需要公开时，写问题类型、设计取舍和可公开结论。

## 纠错

读者通过 Issue 提交纠错时，需要注明文章、段落和依据。作者确认后：

1. 修改正文。
2. 在文章底部写明更正日期和内容。
3. 实质更正写入 `docs/corrections.md`。
4. 如平台版本也有错误，同步更新或追加说明。
